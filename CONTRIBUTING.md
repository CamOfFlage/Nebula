## Code/System Contributions
Follow normal Github procedures for forks, branches, pull requests, etc. Make sure to let everybody know what you're working on, it would really suck if you spent a lot of time developing something only for the basic idea to be rejected or for someone to already be working on it. 

* Code should all follow the standard C# style rules.
* Code should at least attempt to be efficient. It doesn't have to be the best, but it should not cause frame drops for an extended amount of time.
* Code should be legible. If a pull request contains hard to understand code, it will be rejected for revisions.
* All changes should be made in branches until they get pulled to master upon release
* All code should be well documented in XML. If you write a piece of code and submit a pull request without XML it might still be permitted, but you will have to add it back in later, or else you will lose the right to submit undocumented code. (Not *all* code needs to be documented, but most of it should)

#### AI Policy
I know that AI is everywhere, and that it is the first thing to show up on a google search. But any code that is clearly AI generated will be rejected and I will disregard any future pull requests. This is not just limited to vibe coding either, any purely AI written code will be rejected. The maximum usage of AI is purely for research/information and debugging. (This has the scope to be reduced in the future if the lenience is abused)

## Bug Reports
All bug reports should be reproducible, with a detailed description of the issue, and provide the full log and relevant source code. All bugs should be handled through the Issues system on Github. Try to make sure that the bug is due to Nebula's code and not your own code or the game's. Personal usage issues or confusion are not bugs, and should not be reported as such. Instead, feel free to ask for help in the Discord server.

## Suggestions
If you have ideas for future features, post them in the Discord channel or submit them as an "Enhancement" in Github issues.

## Wiki/Documentation Changes
Because Github's wiki system is weird I only have the choice to either let no one edit the wiki or everybody edit the wiki. So if anyone wants to make a change or add a page, just send me a DM on discord.

The wiki is intended to cover all of Nebula's features that require in depth explanation on how to use them. 
It is also useful for it to have descriptions on the game's systems and how they work.
